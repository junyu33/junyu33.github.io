Why does fast inverse square root work?

float Q_rsqrt( float number )
{
	long i;
	float x2, y;
	const float threehalfs = 1.5F;

	x2 = number * 0.5F;
	y  = number;
	i  = * ( long * ) &y;						// evil floating point bit level hacking
	i  = 0x5f3759df - ( i >> 1 );               // what the fuck?
	y  = * ( float * ) &i;
	y  = y * ( threehalfs - ( x2 * y * y ) );   // 1st iteration
//	y  = y * ( threehalfs - ( x2 * y * y ) );   // 2nd iteration, this can be removed

	return y;
}

So what the fuck?

我们假设读者已经熟悉数值分析、IEEE 754 浮点数表示，以及基本的 C 语言知识。

Newton 迭代法

首先看到代码注释里面出现了两次 iteration，我们容易想到 Newton 迭代法，其具体内容如下：

假如我们要近似求解 f(x)=0，并且有一个近似解 xn，在 (xn,f(xn)) 处进行泰勒展开，解析式为

y=f′(xn)(x−xn)+f(xn)

解 y=0 得到 xn+1=xn−f(xn)f′(xn)，依次迭代下去即可接近 f(x)=0 的真正解。

当然这里有两个重要的问题：

  1. 对于初始选取的近似解 x0 有讲究吗？
  2. 收敛速度有多快？

对于第一个问题，答案是 yes。简单的例子形如在 f(x)=x2−2 的 x=0 处做切线，你不会得到与 x 轴的任何交点，因此方法直接失效。另一个更加不平凡的例子是 f(x)=x3−2x+2，可以求得迭代式为 xn+1=xn−xn3−2xn+23xn2−2，如果取 x0=0 开始迭代，则结果会在 0、1 之间横跳，仍然失败。

所以我们有一个直觉：如果我们能取到一个离真正的解比较接近的初始值 x0，那么通常情况下是比较“讲究”的。

对于第二个问题，答案是二次收敛。为了建立相关方法论的直觉，这里我们不考虑一般情况的证明，而是以 f(x)=x2−2 作为具体 case 证明为什么这个函数的牛顿迭代时二次收敛的：

我们知道这个方程的正根是 α=2，迭代式为：

xn+1=xn−xn2−22xn=xn2+22xn

首先我们证明在 xn>0 的情况下一定收敛到 2：首先第一次迭代，均值不等式告诉我们结果一定大于等于 2，然后 xn+1−xn=2−xn22xn≤0，因此序列单调递减有下界，必定收敛。最后令极限为 L，代入 L=L2+22L 得 L=2，证毕。

令误差 en=xn−α，尝试表示

en+1=xn+1−α=xn2−2xnα+22xn=(xn−α)22xn=en22xn

因此我们求得 |en+1||en|2=12xn，前文我们已经得到序列的极限为 2，因此右边趋于一个常数，我们就证明了二次收敛。

初始值近似

然后我们回到 1st iteration 的前五行，根据上一节提到的 Newton 的局限性，我们可以合理猜想 i = 0x5f3759df - ( i >> 1 ); 这一行其实也对结果做了一个粗略但足够“讲究”的初始值近似——我们可以先写一段脚本验证几个值。

ε=y−1/x1/x×100%.

那么紧接着下一个问题就是，为什么这段位运算代码能够用来近似 1/x 的结果呢？其实答案并不难想，我们考虑一个 32-bit 浮点数的 IEEE 754 表现形式：最高的一个 bit 是符号位 S，接下来 8-bit 是指数位 E，最后 23-bit 是尾数位 M。IEEE 754 形式转换成浮点形式的映射公式为：

(−1)S×2E−bias×(1.M)

我们先考虑一个简单的 case：x，那么在不考虑 bias 的情况（也就是 bias=0）下，直接将IEEE 754 表现形式的结果右移一位便是一个不错的估计——因为符号位不变，指数位差不多变成原来的 1/2，尾数位是一团 mess。但由于 log⁡x=12log⁡x，因此这个估计是合理的。

而实际上，bias=127，因此简单的右移一位显然不能 work（尝试代入 1，会直接数量级错误）。实际上，对 E 的处理可以形式化为：

E′−bias=12(E−bias)

进一步化简后，我们发现式子可以统一为 E'=(E+127)>>1，而 127>>1 等于 63，而 0x5f3759df 对应的浮点数是 (1+36274878388608)263。因此我们或许可以隐约感觉到，按照这个思路，是有可能弄清楚源代码那一行的含义的。

现在我们考虑要求的式子本身。同样，log⁡1/x=−12log⁡x，所以我们有:

E′−bias=−12(E−bias)

也就是：

E′=32×127−12E

而 ⌊3×1272⌋=190，刚好就是 0x5f3759df 的指数位！而 12E 也刚好对应了后面 - ( i >> 1 ) 那一步。因为整个 IEEE 754 表示右移一位，指数位的确会变成原来的一半（如果是奇数就再去掉 0.5，但实际上也跑到 mantissa 的最高位了，所以影响不大）。

所以我们可以得出结论，0x5f3759df 这个 magic number 真正重要的是指数位的值，mantissa 最多会影响初始值的精度，进而通过 Newton 迭代影响最终取值的精度，对算法本身的正确性影响不大。

我们会在下下节有更好的尾数吗，讨论尾数如何影响精确程度的问题。

再看 Newton 迭代

接下来到了一个整篇文章最头痛的时刻——我们知道 Newton 迭代的公式是 xn+1=xn−f(xn)f′(xn)，但实际上我们的代码是 y = y * ( threehalfs - ( x2 * y * y ) );，长得有点像，但一眼也没法直接套上去。

问题的瓶颈就出在，我们知道根是 1/x，但满足这个根的方程却有很多，那么哪一个可以对上这段代码呢？或许有人可以直接“注意到”，但至少我这次没有成功。于是我开始直接列出方程：

y−f(y)f′(y)=y(32−x2y2)

整理后得到

2f(y)=(xy3−y)f′(y)

这里 f 是关于 y 的函数。于是我们得到了一个 ODE，但是我已经早已忘记了 ODE 是如何求解的，于是我求助了 GPT 并得知了以下方法：

对于形如

f′(y)=g(y)f(y)

的微分方程，只要在 f≠0 的区间上，两边除以 f(y)：

f′(y)f(y)=g(y)

注意：

ddyln⁡|f(y)|=f′(y)f(y)

因此直接积分：

ln⁡|f(y)|=∫g(y)dy+C

这就是一阶可分离变量微分方程最基础的求解方法。

你的方程正好属于这一类，并不需要学习高阶 ODE、常微分方程组或数值 ODE。

那么学习完之后，代入 g(y)=2xy3−y，即可得到：

ln⁡|f(y)|=∫2xy3−ydy+C

对于分式积分，我还依稀记得需要拆开，先换成比较熟悉的符号：

∫2ax3−xdx=∫2ax3−xdx=∫(ux+vx+wax2−1)dx

通分后也就是 (au+v)x2+wx−u≡2，解方程后可得 u=−2,v=2a,w=0，代入后继续积分：

∫(−2x+2axax2−1)dx=−2ln⁡|x|+ln⁡|ax2−1|+C=ln⁡|a−1x2|+C

把符号换回来，就是：

f(y)=C(x−1y2)

验证一下 1/x 的确是 f 的零点，这就证明了 y = y * ( threehalfs - ( x2 * y * y ) ); 这一行代码的确就是标准的 Newton 迭代步骤。

有更好的尾数吗？

假如我们的浮点数都是正规的，现在回到之前忽略的尾数问题。假如我们不考虑尾数的 mess，把代码改成 i = 0x5f000000 - (i >> 1);，对于一些较为极端的例子，误差结果如下：

1 0.75 1 −25.000%

并且可以证明，在保持 magic number 为 0x5f000000 的情况，对于任何输入 x，最大的相对误差就是 1−22≈−29.289%。（证明略）

如果连尾数都可以自由选取（从 0x5f000000 到 0x5f7fffff），那么全局最大误差出现在 4/3 处，但实际上受浮点精度限制，对应的 round 值约为 1.33333337，算出来的最大误差 εmax 为（相对于 1.33333337）：

εmax=1.333333253−0.8660253910.866025391≈+53.960065%

与前文约 3% 左右的误差还有数十倍的差距，这也不是靠一次 Newton 迭代就能完全追上的——这就来到了算法准确性的部分。

为了选取最好的 magic number，我们可以设计这样的筛选策略：

  • 直觉告诉我，尾数 M 的轻微变化应该不会让误差 turbulence，因此我们可以先分段选取样本，步长比如说为 0x1000，从 0x5f000000 到 0x5f7ff000 。
  • 对于输入 x，随机抽 10000 个 binary32 范围内的正数并计算误差；之后的 0x1000 步长内部的遍历环节，再随机抽 10000 个 binary32 范围内的正数并固定，让这 4096 个 magic number 计算各自误差，然后选出误差最低的那几个。

然后这里就引来了一个重要问题——如何定义“最好”，或者说“误差最小”？作为写过论文的人，我当即想出了几种 metric：

  • geomean 最小：用于衡量整体的误差程度，只不过误差为 0 的时候需要使用极小 ε 替代；
  • average 最小：考虑 outlier 给数据带来的影响；
  • minimax（最极端的误差）最小：极端 outlier 的 weight 最重。

我这里选择的第三种 metric，因为这段代码是出自 FPS 游戏 Quake III Arena。作为游戏玩家的哲学，就拿 FPS 来说，肯定是希望“平均略坏”大于“突然卡住”，所以我们要尽可能优化最坏的情况。

选择适合的优化目标后，我们开始第一步的粗筛，并尝试分析 magic number 与 minimax 值的函数关系（前文我猜测应该没有 turbulence）。为了方便复现，这里的随机数种子是 0xC0FFEE，绘图如下（完整实验代码见附录 A：Minimax 粗筛绘图程序）：

可以发现，我的直觉是正确的，图像确实形成了一个 V 形结构。进行 0 次 Newton 迭代（蓝色）和 1 次迭代（黄色），均在 0x5f376000 处分别取到了 3.427736% 和 0.176516% 的极值。

接下来是确定精筛的范围，我们可以有对 V 形函数有以下直觉：如果 f(a)>f(b)<f(c), a<b<c，那么最小值一定出现在 (a,c) 之间。对于这道题，我们遍历 [0x5f375000, 0x5f377fff] 这个区间就应该足够（代码见附录 B：Minimax 精筛绘图程序）。

然后，有趣的事情发生了：我们发现 0 次迭代的最优值和 1 次迭代的最优值并不一致！前者是 0x5f37642e，后者是 0x5f375a71 和 0x5f375a73 并列第一。两者的函数图象如下：

这就意味着一个非常神奇的现象——牛顿迭代法并不保证对于两个初始误差 e1<e2，迭代过后的误差 e1′ 仍然小于 e2′。具体原因是什么，可能就涉及到诸如函数本身的性质，以及之前提到过的初始值的“讲究”程度了，这里讲起来比较复杂，文章就跳过了。

当然，另外一个问题是，为什么这两个结果都和原始 magic number 0x5f3759df 虽然很接近，但又不完全一致呢？原因其实是比较 mundane 的：样本量不够，导致选取的样本集合有某种统计意义不可避免的 bias（感性理解就是你投 1000 次币，不太可能刚好正面 500 次反面 500 次，总得偏向某一边几次十几次一样），导致精筛的时候出现针对该样本的“局部最优”。

解决办法也很暴力：覆盖所有不同的相对误差模式。我这里选取的是 [1,4)（为什么？）的全部 224 个正规输入并比较 minimax（代码见附录 C：区间 [1,4) 最优求解）。实验组是我们前两个脚本算出来的“最优值”，对照组是 Chris Lomont 的那篇 Fast Inverse Square Root 论文：

64 位的情况又如何？

我们概括一下之前 32 位的分析，我们主要探索了以下几个问题：

  1. 什么是 Newton 迭代？
  2. 这段代码前面的 shift 部分的大概直觉，确认指数部分的取值。
  3. 理解最后那一行确实在做 Newton 迭代。
  4. 筛选尾数部分，找到在 minimax 意义下的最优解。

而 Newton 迭代公式本身并不会因为从 binary32 变成 binary64 就有所改变，因此问题 1 和 3 无需重新探索，只用看 2 和 4 即可。

对于问题 2，solution 是 immediate 的，因为公式

E′−bias=−12(E−bias)

仍然成立，只不过 bias 从 127 变成了 1023，经过计算后得知指数位为 1534。

对于问题 4，此时 magic number 的搜索空间从原来的 223 变成了 252，即使使用之前的粗筛+精筛法，成本也基本不可行。但注意到我们之前在 binary32 中发现 magic number 和误差的函数关系是一个 V 字形，是一种单峰函数。除了最 naive 的遍历之外，我也立刻想出了三分的做法——那是因为五年前我校测机试的 OI 部分也考到了这个，那真是一段令人怀念的岁月啊。

当时那段回忆录我写：

“回到2题，我抛弃了数学方法并尝试三分，仍然因为精度问题爆零，我气愤地把所有的变量全部改为double，事情便有了进展，获得了8分的好成绩。”

这里那道题的满分是 10 分。当年我用 double 来优化当时的三分算法，现在我又用三分来优化 FISR 在 double 情况下的 magic number，挺美妙的。

回到正题，三分的思路本身很简单，对于有极小值的单峰函数 f，初始区间 [a,b]，令两个三等分点 m1=23a+13b，m2=13a+23b：

  • 若 f(m1)>f(m2)，则更新 a=m1；
  • 若 f(m1)≤f(m2)，则更新 b=m2；
  • 为了 robustness，当 b−a 小于某个设定的距离 Δ 后，就可以恢复穷举了。

对于本文的 case，f 的 evaluate 方式仍然是固定随机种子 0xC0FFEE，计算 10000 个随机正规 binary64 值的 minimax。选取的 Δ=512，并分开评估 0 次和一次 Newton 迭代的情形。实现见附录 D：三分搜索。初步实验结果如下：

做 1 次 Newton 迭代出现的 discrepancies，解释也比较容易：

  • 等距的话就相当于完全公平的抛硬币正 500 反 500 情形，没有 bias；
  • random 就是最不均匀的，容易出现过拟合，并在等距 case 中出现明显退化；
  • binary32 网格由于 IEEE 754 表示本身就不 even，但也远好于随机数选择的 bias，所以效果介于两者之间。
